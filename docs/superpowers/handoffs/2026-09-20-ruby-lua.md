## Publication order

1. Publish the permanent site commits through
   `4a13b5714224125636b027d23991117c3c56a81f` to a public `libtmux/docs`
   branch. Both port callers must be able to resolve that exact object.
2. Configure `docs`, `docs-preview`, and `docs-preview-cleanup` environments
   in each port repository. Restrict them to the intended refs and verify the
   resulting OIDC subject conditions.
3. Configure repository- or organization-level
   `LIBTMUX_DOCS_BUCKET`, `LIBTMUX_DOCS_DISTRIBUTION`,
   `LIBTMUX_DOCS_ROLE_ARN`, and `LIBTMUX_DOCS_PREVIEW_ROLE_ARN` secrets.
   Configure `LIBTMUX_DOCS_PREVIEW_CLEANUP_ROLE_ARN` where the cleanup job can
   read it.
4. Restrict the production role to `en/<port>/*` and
   `manifest/<port>.json`, the preview role to `en/<port>/pr-*`, and the
   cleanup role to deletion within that preview space.
5. Push each `docs-site` branch to its public repository and open the port PRs
   from the prepared descriptions. Do not push from the docs integration
   worktree.
6. Publish the Ruby and Lua default trees before running the site shell job
   that merges manifests and refreshes Pagefind, the sitemap, shared assets,
   landing pages, and redirects.
7. Close a real preview PR and prove only its exact prefix is removed. Recheck
   trunk, aliases, immutable releases, other ports, search, canonical URLs,
   robots directives, and default redirects.

repositories have no homepage. After the canonical production pages work,

prepared gemspecs point the next authorized releases at their canonical core,
MCP, workspace, or reference pages; existing RubyGems records cannot be
changed by this documentation branch. The current Lua rock points to GitHub.
Set its documentation homepage to the canonical release page in a subsequent
authorized rock release after that URL is live.
