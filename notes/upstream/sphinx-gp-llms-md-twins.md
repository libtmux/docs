# Generated pages link to a .md twin that was never written

`genindex`, `search` and `py-modindex` each carry a link to
`<pagename>.md`, and none of those files exists. Every one is a 404 on a
built site.

## Cause

The link is injected unconditionally; the file is written conditionally.

`_inject_llms_context` runs on `html-page-context`, which fires for every
page the HTML builder renders:

```python
if app.config.llms_generate_md_twins:
    context["llms_md_url"] = pagename + ".md"
```

`write_md_twins` iterates `app.env.found_docs`, which holds only real
source documents, and skips even those whose source has gone:

```python
for docname in sorted(app.env.found_docs):
    ...
    source_path = pathlib.Path(app.env.doc2path(docname))
    if not source_path.exists():
        continue
```

`genindex`, `search` and `py-modindex` are generated by Sphinx and are
not in `found_docs`, so they get the link and never the file.

## Reproducing

Any `dirhtml` build with `llms_generate_md_twins` on:

```console
$ rg -o 'href="[^"]*genindex[^"]*"' _build/genindex/index.html
../genindex.md
$ ls _build/genindex.md
ls: cannot access '_build/genindex.md': No such file or directory
```

Seen on gp-sphinx 0.1.0a37 / sphinx-gp-llms 0.1.0a37, building
`tmux-python/libtmux` to dirhtml. Two 404s per version built.

## Suggested fix

Gate the injection on the same condition as the write — the page having
a source document:

```python
if app.config.llms_generate_md_twins and pagename in app.env.found_docs:
    context["llms_md_url"] = pagename + ".md"
```

`found_docs` is available on `app.env` in the `html-page-context`
handler, so this needs no extra bookkeeping. It would also cover the
second case the writer already handles — a document whose source file
has disappeared — which currently gets a link too.

`_has_twin` applies the writer's own two conditions at the injection
site, so the two cannot drift apart again. Three tests fail without the
fix; the whole `tests/ext/llms/` suite (37 tests), ruff and mypy pass
with it.

The tests assert against the handler rather than the built HTML,
deliberately: the link is rendered by a theme template and the suite
builds with `basic`, which has none. An HTML-level assertion passes
whether or not the bug is present, which is how this survived.
