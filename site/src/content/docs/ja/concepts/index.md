八つの実装、その下にあるのは一つの tmux です。個別の API リファレンスを開く
前に、八つすべてが同意しているモデルと、実装ごとに本当に違っている部分を
押さえておくと役に立ちます。Python の `.filter()` が TypeScript の
`.where()` と似ていないこと、「キーを送る」処理がある実装ではサブプロセスの
一回の呼び出しで、別の実装では持続的な接続であること — こうした違いに驚かず
に済みます。

このセクションでは、すべての実装が共有している、あるいは意図的に違えている
四つの事柄を扱います。

- **[サーバー、セッション、ウィンドウ、ペイン](/concepts/server-session-window-pane/)** —
  tmux 自身が定義するオブジェクト階層と、その外側にある唯一の存在
  (アタッチ中のクライアント)。
- **[コントロールモードとワンショット](/concepts/transports/)** —
  プログラム内の呼び出しが実際に tmux サーバーへ届くまでの経路。コマンドごとの
  サブプロセス、持続的なコントロールモードのクライアント、あるいは複数の
  コマンドを一回の呼び出しにまとめる方式。
- **[フィルタリングとクエリ](/concepts/queries/)** —
  「サーバー上のすべてのセッション」から「目的のペイン一つ」へ絞り込む方法と、
  一致が零件または複数件だったときに何が起きるか。
- **[ワークスペース](/concepts/workspaces/)** —
  複数ペインのレイアウトを手作業ではなくコードから組み立てる方法と、
  多くの実装がオブジェクト API と併せて提供する tmuxp 型の宣言的ビルダー。

ここにあるのは特定の実装のリファレンスではありません。それが必要な場合は、
実装切り替えから各実装の API ページへ移動してください。このセクションが扱う
のは、実装のあいだを移動しても変わらないこと — そして、興味深いことに
変わってしまうことです。
